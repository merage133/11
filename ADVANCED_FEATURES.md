## ✅ Реализованные функции

### 1. 🔒 Middleware подтверждения опасных действий

**Проблема:** AI мог выполнить опасные команды (выключение, перезагрузка) без подтверждения.

**Решение:** WebSocket-based система подтверждения.

**Как работает:**
1. AI вызывает опасный инструмент (shutdown_pc, restart_pc)
2. Сервер отправляет WebSocket-событие `ACTION_REQUIRED` на фронтенд
3. Появляется модальное окно: "AI хочет выполнить: [действие]. Разрешить?"
4. Пользователь нажимает [Да] или [Нет]
5. Без явного подтверждения команда НЕ выполняется

**Технические детали:**
- WebSocket сервер на порту 3002
- Компонент `ActionConfirmation.tsx` для UI
- Таймаут 60 секунд для ответа
- Все опасные действия требуют подтверждения

**Пример:**
```
AI: Вызываю shutdown_pc...
[Появляется модальное окно]
"AI хочет выполнить: Выключение компьютера через 5 секунд. Разрешить?"
[Да] [Нет]
```

### 2. 📊 Индикаторы выполнения инструментов

**Проблема:** Когда AI вызывает инструменты (поиск, компиляция), пользователь думает что всё зависло.

**Решение:** Информативные статусные сообщения для каждого инструмента.

**Индикаторы:**
- 🔍 `search_internet` → "AI ищет в интернете..."
- 💱 `get_exchange_rate` → "AI получает курс валют..."
- 🌤️ `get_weather` → "AI проверяет погоду..."
- 🕐 `get_current_time` → "AI узнаёт время..."
- 📸 `take_screenshot` → "AI делает скриншот..."
- 📁 `list_files` → "AI просматривает файлы..."
- 📖 `read_file` → "AI читает файл..."
- ✍️ `write_file` → "AI записывает файл..."
- 💻 `run_command` → "AI выполняет команду..."
- ⚙️ `compile_and_run` → "AI компилирует и запускает код..."
- 📚 `search_knowledge_base` → "AI ищет в базе знаний..."
- ⚠️ `shutdown_pc` → "AI запрашивает выключение..."
- ⚠️ `restart_pc` → "AI запрашивает перезагрузку..."

**Где отображается:**
- В верхней панели (statusText)
- В процессе выполнения инструментов

### 3. 🔍 Фоллбэк для поиска (DuckDuckGo)

**Проблема:** SearXNG требует отдельной установки (Docker), что убивает концепцию "Quick Start".

**Решение:** Добавлен фоллбэк через npm пакет `duck-duck-scrape`.

**Как работает:**
1. Сначала пробуем SearXNG (если установлен)
2. Если SearXNG недоступен → используем `duck-duck-scrape`
3. Если и это не работает → используем Wikipedia API
4. Если ничего не работает → DuckDuckGo HTML парсинг

**Преимущества:**
- ✅ Не требует внешних сервисов
- ✅ Работает из коробки
- ✅ Бесплатно
- ✅ Без API ключей

**Установка:**
```bash
npm install duck-duck-scrape
```

### 4. 🤖 Реализован цикл ReAct (Reasoning + Acting)

**Проблема:** Сложные задачи требуют нескольких шагов, но AI не мог их выполнять автоматически.

**Решение:** Цикл ReAct с лимитом итераций.

**Как работает:**
```
1. Отправляем запрос модели с инструментами
2. Если модель возвращает tool_call:
   - Выполняем инструмент
   - Получаем результат
   - Возвращаем результат модели как сообщение с ролью 'tool'
   - Модель продолжает генерацию
3. Повторяем пока:
   - Модель не вернет обычный текстовый ответ
   - Или не достигнем лимита (10 итераций)
```

**Пример сложной задачи:**
```
Пользователь: "Найди курс доллара, сохрани в файл rate.txt и открой его"

AI: [Итерация 1]
  → Вызывает get_exchange_rate("USD", "RUB")
  → Получает: "Курс: 83.55"

AI: [Итерация 2]
  → Вызывает write_file("rate.txt", "Курс доллара: 83.55")
  → Получает: "Файл записан"

AI: [Итерация 3]
  → Вызывает run_command("start rate.txt")
  → Получает: "Команда выполнена"

AI: [Финальный ответ]
  "Я нашёл курс доллара (83.55 рублей), сохранил его в файл rate.txt и открыл файл."
```

**Технические детали:**
- Максимум 10 итераций (предотвращает бесконечный цикл)
- Каждая итерация показывает статус в UI
- Все промежуточные результаты сохраняются в истории

### 5. 📚 Векторная база знаний (RAG)

**Проблема:** Старая "База знаний" просто пихала текст в контекст, что неэффективно для больших документов.

**Решение:** Векторный поиск через LanceDB + эмбеддинги через Ollama.

**Как работает:**
1. Пользователь добавляет документ (PDF, TXT, MD)
2. Документ разбивается на чанки (500 символов)
3. Для каждого чанка генерируется эмбеддинг через Ollama (модель `nomic-embed-text`)
4. Эмбеддинги сохраняются в LanceDB
5. При запросе AI:
   - Генерирует эмбеддинг запроса
   - Ищет похожие чанки в векторной БД
   - Получает только релевантные куски
   - Экономит контекст модели

**Технические детали:**
- LanceDB для векторного хранения
- Ollama `nomic-embed-text` для эмбеддингов
- Топ-3 релевантных чанка для каждого запроса
- Автоматическое разбиение на чанки

**Установка:**
```bash
# Установить модель для эмбеддингов
ollama pull nomic-embed-text

# Установить зависимости
npm install lancedb apache-arrow
```

**Пример:**
```
Пользователь: [Загружает PDF "Документация API.pdf"]
AI: [Разбивает на 150 чанков]
AI: [Генерирует эмбеддинги]
AI: [Сохраняет в LanceDB]

Пользователь: "Как авторизоваться в API?"
AI: [Ищет похожие чанки]
AI: [Находит 3 релевантных чанка]
AI: "Для авторизации используйте endpoint /api/auth с параметрами..."
```

### 6. 📝 Суммаризация истории

**Проблема:** Длинная история диалога превышает лимит контекста модели.

**Решение:** Автоматическая суммаризация когда история превышает N токенов.

**Как работает:**
1. Подсчитываем токены в истории
2. Если токенов > 10000:
   - Отправляем историю модели с промптом: "Суммаризируй эту историю в 3 предложениях, сохранив ключевые факты"
   - Получаем саммари
   - Заменяем старую историю на саммари
3. Продолжаем диалог с саммари

**Технические детали:**
- Лимит: 10000 токенов (настраивается)
- Промпт для суммаризации в `config.ts`
- Саммари сохраняется как первое сообщение в истории
- Оригинальная история удаляется

**Пример:**
```
[История: 15000 токенов]

AI: [Автоматически суммаризирует]
"Пользователь работал над проектом Mirage AI. 
Основные задачи: добавление голосового ввода, исправление багов с поиском, 
настройка автоматической проверки кода. 
Последнее: реализован ReAct цикл и векторная база знаний."

[История теперь: ~500 токенов]
```

## 🏗️ Архитектура

### WebSocket сервер (порт 3002)
```
Frontend (React) ←→ WebSocket ←→ Backend (Node.js)
     ↓                                    ↓
ActionConfirmation              requireConfirmation()
```

### ReAct цикл
```
User Query
    ↓
Ollama (с tools)
    ↓
[tool_call?] ──Yes──→ Execute Tool → Get Result → Back to Ollama
    ↓ No
Final Answer
```

### RAG pipeline
```
Document → Chunking → Embeddings (Ollama) → LanceDB
                                                ↓
User Query → Embedding → Vector Search → Top-K Chunks → Context
```

## 🔧 Настройка

### Включение/отключение подтверждения

В `server.cjs`:
```javascript
// Список опасных действий требующих подтверждения
const DANGEROUS_ACTIONS = ['shutdown_pc', 'restart_pc', 'run_command'];

async function requireConfirmation(action, description) {
  if (!DANGEROUS_ACTIONS.includes(action)) {
    return true; // Автоматически разрешаем
  }
  // ... остальной код
}
```

### Настройка лимита токенов для суммаризации

В `src/App.tsx`:
```javascript
const MAX_HISTORY_TOKENS = 10000; // Измените по необходимости
```

### Настройка количества итераций ReAct

В `src/App.tsx`:
```javascript
const maxIterations = 10; // Максимум итераций для ReAct цикла
```

## 🐛 Решение проблем

### WebSocket не подключается
```bash

node server.cjs

# Проверьте порт 3002
netstat -ano | findstr :3002
```
